## Implemented behavior

1. Friend explicit retry reads the original receipt and, when it is UNKNOWN,
   rechecks both the durable operation identity and protected original command
   immediately before calling the existing writer. Another recovery page settling
   or replacing the original during that read prevents replay. An unchanged
   original still replays the exact request ID and command. No automatic replay
   or replacement request ID is introduced.
2. Webhook HTTP 5xx or business 5xx after dispatch remains UNKNOWN, including an
   HTML gateway response or a conflicting error body. Restart retains the same
   journal identity. Resource/delivery/inbound pages reject duplicate IDs,
   over-limit rows and empty nonterminal pages; filtered log responses must match
   the requested state. Original service, provider and journal remain in use.
3. Push-attempt GET readback bounds response size, validates canonical decimal
   IDs, rejects duplicate rows and ensures an exclusive `before` page and its next
   cursor move toward older IDs. A malformed page remains unavailable; UNKNOWN
   attempts remain UNKNOWN. This adds no token registration, APNs call, retry,
   delivery acknowledgement, credential, or permission.
