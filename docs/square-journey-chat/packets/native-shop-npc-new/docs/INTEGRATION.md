# Shop NPC node conversation: isolated additive package

## Source truth
- `app-audit/lib/data/api/ai_npc_api.dart:70–166`: POST `/api/ai/npc/shop-chat` JSON exactly `{requestId,nodeId,message}`; POST `/api/ai/npc/voice-chat` multipart exactly `file,nodeId,requestId`. AjaxResult body code must be 200 even with HTTP 200. Preserve server message verbatim.
- `lib/data/models/shop_npc_models.dart`: nonempty `data.safeText` wins over `data.text`; voice `asr` is top-level, never `data.asr`. The source provides no reply audio field; audio playback stays explicitly unavailable. No TTS/provider contract is invented.
- `lib/feature/play/free_explore/card_detail_page.dart:124–141`: only nodes with NPC data can open `ShopNpcPage(sessionKey,nodeId)`. `shop_npc_page.dart:174–288` handles questions, regeneration, and voice. Message history is client-owned, not a fictional server read endpoint.
- `lib/feature/play/free_explore/shop_npc_voice.dart`: AAC-LC/m4a, 16 kHz mono, 32 kbps, 0.5–60 seconds, local temporary cleanup. Source explicitly documents backend `transcribe(bytes,"mp3")` mismatch and Noop ASR. `voiceFormatVerified` must remain false until backend deployment handles actual m4a and provider availability is verified. This is not resolved by renaming m4a to mp3.

## Identity boundary correction
Public merchant home is a **different conversation contract**. `merchant_public_home_page.dart:405` calls `showMerchantNpcChatSheet(merchantId:data.id)`; `lib/feature/npc/merchant_npc_chat_controller.dart:134` calls `MerchantNpcApi.chat`; `lib/data/api/merchant_npc_api.dart:65–81` uses POST `/api/ai/npc/merchant-chat` JSON `{requestId,bizId:merchantId,message}`. Do not connect `PublicMerchantHomeContext.npcDestination(PublicMerchantRowID, NPC)` to ShopNPC, cast merchant IDs into node IDs, or invent a mapping endpoint. Keep the existing public merchant card/hook unchanged for a separate merchant-chat package. This package does not duplicate public merchant reads.

Related separate merchant source paths: `lib/data/api/merchant_npc_api.dart` voice/script, voice/enroll, voice/status, voice/revoke, avatar/status, avatar/generate; `lib/data/models/merchant_npc.dart`; `lib/feature/merchant/merchant_npc_voice_page.dart`; `merchant_npc_avatar_page.dart`; `lib/feature/npc/widgets/merchant_npc_chat_sheet.dart`.

## Additive host wiring
1. Copy manifest `copy` files into `chengyin-ios`; merge string catalog into existing Localizable.xcstrings preserving unrelated keys. No shared-main files were changed by this package.
2. Inject `ShopNPCHTTPTransport` using the app's authenticated central client and production write gate. Validate request.scope against the currently authenticated account/session/role/access revision again immediately before dispatch. Do not implement it with an unauthenticated standalone upload or OSS helper. Errors after dispatch are unknown outcomes, never proof a charged model call did not happen. The package intentionally supplies no network-enabled default transport.
3. On the authoritative free-explore node detail, add `ShopNPCNodeEntrance(name:makeCoordinator:greeting:)`. Supply the current node ID as `ShopNPCNodeID`; resolve NPC name/greeting from the active node data at navigation time. Build a fresh coordinator for each destination. Pass session ID, account ID, role ID and access revision from the current authenticated play session. Missing NPC name means no entrance. This entrance is fully authored but not mounted in the shared app yet.
4. Server/provider/legal/access grants all start false. Set only from verified host policy and explicit product opt-in, not from a static fixture or merchant image/name. Call `rebind` on every relevant identity/role/node/access/grant change and `invalidate` on logout/route teardown. Rebinding invalidates in-flight deliveries and clears private drafts/history. Provide new view/coordinator identity after background invalidation; backgrounding deliberately does not silently resume.
5. Text review binds exact content and scope. Only Confirm and Send performs a request. Unknown-outcome retries retain the same UUID. Regeneration requires its own review and preserves the existing answer/ID on failure. Local one-second pacing is a UI safeguard, not a claim about server quota. HTTP 429 is explicitly represented; business error code/message are preserved.
6. No capture provider is installed by default. If voice is explicitly enabled after source format discrepancy is fixed, inject `ShopNPCAVCapture` only after an explicit microphone intent and separate OS permission workflow. It will not request permissions itself. Add NSMicrophoneUsageDescription only as part of that approved host integration. Stop prepares an in-memory clip for review; cancelling/background/exit removes temporary files and never uploads. The 60-second provider timeout discards the clip. A provider callback clears the UI recording state after timeout/cancellation.
7. Do not turn an AI reply into completion, check-in, proof, receipt or a game progress mutation. No such integration exists here. Copy uses native selectable text; no media auto-fetch, playback, recording, permission prompt, provider call, or network call occurred during authoring.
