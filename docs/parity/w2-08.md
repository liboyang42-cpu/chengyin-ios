# w2-08 roam-core — mini-program → iOS parity

Scope: `pages/roam/index` (roam tab), `subpackageRoam/{citynode-code, history, poi-detail, session, nearby, citystamp, my-teams}`, `pages/searchmap/index`.

Source of truth: `liboyang42-cpu/hengyin` master `e1ae751`, `chengyinhub-xcx/`. No roam, subpackageRoam or searchmap file changed between the earlier area-D audit snapshot (`4667f71`) and `e1ae751`. Base: `migration/native-ios` plus `cloud/align-D-20261019` and `cloud/plan-F-20261019`.

Status values:
- **parity**: fields, actions, states and copy match. Live behaviour is limited only by the repository rules below.
- **partial**: some items are missing; the gaps are listed.
- **blocked**: needs a live write, device location, camera, or an endpoint review.

Repository rules that apply to everything here:
- The reviewed endpoint allowlist stays empty.
- New readers return nil from `AppCompositionRoot`, so production shows an honest "unavailable" or "not configured" state.
- Writes stay dormant.
- There is no device-location sampling. The manual roam area or map centre is the query context.

Apple builds, XCTest and XCUITest were **not run**: the Linux environment has no Swift toolchain. The checks that were run are listed at the end.
