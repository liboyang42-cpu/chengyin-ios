## Per page details

### governance
API: `access/me` (skipped for own-cases so a banned member can appeal), `members`, `governance/list`, `governance/cases/mine` (top-level `activeBan` now carried as `{data, activeBan}`), writes `ban` (7/30/90-day picker → `expiresAtEpochMs`, ≤ 90 days), `unban` (optional reason), `owner/transfer`, `cases/report`, `cases/appeal` (appeal offered only with a known active ban).
Rows: ban source/status/expiry copy, 仅平台可解封, 解封说明; case type/status/提交于/平台说明; per-page denied/empty copy; success copy only after confirmed receipts.

### roles
Assignments joined client-side with `/api/club/members` names (fallback 成员 #id), role name/summary, `至 MM-DD`, pinned owner row (全部权限，不可撤销); revoke sends the fixed reason 主理人在角色管理页撤销 with the danger confirm copy; `activityId`-scoped event roles unchanged.

### event-ops
Hub `ClubOpsEventView` (活动运营) reachable from the workspace and from an event (现场名册与核销), mini section order, denied copy and 仅核销权限可见. Correction direction now derives from the roster tab (标记到场 / 更正未到, none on 候补), Shanghai correction window, disabled 现在不能更正. Create defaults: waitlist on, 4 weekly occurrences; edit hides capacity/waitlist/lead. Explicit 主理人（默认） lead sends `null` (create only). Cancel: 2–255 reason, second confirm, fail-closed readback (本场已取消 / 原因 / refund + notification summary / 重新回读). Occurrence date `M月d日 周X HH:mm` (Shanghai) and badges/meta.

### customers / customer-detail
Count line, row meta (待核销 N 张 · 最近参加「X」 / 核销 N 次 · 最近 MM-DD), remark-or-phone sub line, empty / filtered-empty / error / denied copy. Detail: 最近互动, 累计实付 (`¥` or 无查看权限, never invented), 客户概览, 参与记录 statuses (CANCELLED no longer rejects the whole response), tags/remark chips and inline editor with 200/12/8 limits. `saveCustomer` permission tightened to the customer-directory rule (owner / legacy admin / `club:member:manage`), matching backend `requireGovernable`. Alignment P0-9 verified equivalent.

### settlement
已入账分润 card / 金额待核验 / N 笔…待核验, 各主题结算 rows with status chips, mini footnote, empty/error copy; owner funds hints; non-owner sees disabled 联系平台客服提现 with 仅主理人可发起提现.

### join-requests
P0-7 closed: the reject confirmation carries an optional 拒绝原因（选填） (≤ 500 UTF-16 units, matching backend `ClubMember.reviewReason`), frozen into the same confirmation and sent as `reviewReason` only for reject with a non-blank reason; an access without reason support refuses rather than silently dropping it. Preflight, single send, outcome-unknown lock and readback unchanged. Intro line `N 条待审 · 可直接通过或拒绝`, applicant fallback 城瘾玩家, decoded join message, approve/reject consequence copy.

### notify
选择受众 with `N 人` counts (null stays blank), 标题*/内容* with 80/1000 counters and inline range messages, review preview `N 人`, receipt outcome line (站内通知已发送 / 部分发送失败 / 通知已提交，正在投递 / 仍有失败项 / 失败项已重试), `.notificationStatus` card (已投递完成 / 部分未送达 / 投递中, 总人数, 已送达站内, 待投递, 失败) with 只重试失败项; event-only audiences explain 当前角色没有本场通知权限.

### workbench
Mini-program page is only a redirect shell (`onLoad` → `club/detail?id&tab=manage`). The equivalent in-app entry is the club workspace button on club detail. Legacy link handling is blocked as listed above.
