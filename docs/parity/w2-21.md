## What the W20 section shows (plan §29–35)

- Rules version, actions left this round (server pair or "Not published"), holdings vs server limit, the member's **existing** points (no city coin, no team wallet) — W20.1, W20.7, §30 note.
- Per property: neutral vs operable role; AVAILABLE / HELD / PROTECTED (with server end time) / PAUSED (brand-centre pause) / SAFETY_BLOCKED (overlay, "do not travel there"); own-team marker; async challenge state (W20.14); "completed task kept" after a conflict (§32).
- Services with a published fee, free services, and undisclosed fees that cannot be accepted (W20.5–W20.6).
- Actions only from server facts: start round (server `roundSeq`), accept task, acquire, accept service, start challenge. None while the board is FROZEN/CLOSING/CLOSED, not joined, out of budget, paused or blocked. Neutral goals stay available at zero points (W20.6).
- Paid actions: server quote → review card (points cost, actions used, payer = you, beneficiaries, rule version, quote expiry, "teammates are never charged") → explicit confirm. A quote naming another payer is refused; insufficient balance never sends (W20.4, W20.13).
- Exactly one in-flight intent; unknown result → "Check result" (receipt readback by requestId) or "Retry same request" (identical intent); QUOTE_CHANGED → never auto-accepted; EFFECT_ALREADY_APPLIED / BLOCKED / VERSION_CONFLICT (task kept) shown (W20.11–W20.13). A snapshot never settles an unknown outcome.
- Snapshot + ordered deltas with agent H's `CityDeltaStream`; gaps reload the snapshot (W20.16).
- Privacy copy: a held pin is board state, never the operator's presence; no opponent locations (W20.17). The projection carries no coordinates; properties must sit on reviewed visible points.
