## Changes in this branch

- **tixianjilu** — new `WithdrawalHistoryRow/Page/Coordinator` reproduce the source mapping:
  amount = `receivedAmount` with two decimals and a leading minus, `—` when missing/non-numeric;
  status 0 提现中 / 1 提现成功 / 2 提现失败，提现金额已全部退回 / anything else 状态待确认 (one odd row
  no longer fails the table); data array, `{rows}` or `{list}` accepted, anything else is an error,
  never empty; 401 → sign-in state, 403 → access-denied state, other failures → retry.
  Closes alignment E P0-2 for the reachable entries (wallet home and withdrawal page).
- **tixian** — adds 提现方式 / 提现说明 / 联系客服提现 (opens the existing reviewed support sheet; no
  contact is embedded) and points the 提现记录 entry at the new history view.
- **coupon-qr** — server code 503 shows 优惠券出示码暂不可用 and stops automatic refresh and polling
  until an explicit retry; the not-started state shows the start day and 重新获取; the ready state
  adds 出示给商家扫码核销 and 刷新二维码; validity is shown on the expired result only; a missing
  coupon id shows 缺少券信息 / 请返回票夹重新进入.
- **coupon-wallet** — empty and filtered-empty copy aligned (English titles pinned by UI tests kept).

## Gaps and decisions

1. `WalletWithdrawalsView` (old mapping: `withdrawalAmount`, 0–3 review statuses, missing status fails
   the table) is still reachable from the dormant `BankWithdrawalView` and the DEBUG wallet fixture,
   and its behaviour is pinned by existing Core/UI/contract tests. Retiring it needs an explicit
   test-retirement review; left in place.
2. The mini-program retired the bank-card form (2026-09-16, offline support only). iOS still shows
   the dormant `BankWithdrawalView` entry on the withdrawal page; contract tests pin that entry.
   Decision needed: remove the entry (retire those checks) or keep it as a dormant reference.
3. tixian's `roleGuard.can('withdrawable')` gate (from `api/role/info`) has no iOS reader; iOS gates
   the entry through the host's `WalletCommerceVisibility.withdrawalRecords`. Blocked on a role
   permission reader (outside this scope).
4. tixianjilu `theme=merchant` only changes colours in the source; iOS uses system styling.
5. All reads stay behind the reviewed per-market endpoint allowlist (currently empty); offline
   fixtures: `--wallet-commerce-fixture --withdrawal-parity=<rows|empty|denied|unauthorized|failure>`.
