## Play guide (`infomation`, `infomationdetail`)

Source calls: `POST /api/common/infomation_list` (form `pageNum=1&pageSize=10`, ignored by the backend, all rows by `sort_id DESC`),
`POST /api/common/infomation_detail` (form `id`), `POST /api/template/homeData` for "现成玩法". All anonymous reads; no writes.
iOS already used the same three calls (`ProfileGuideReadRoute`, `DiscoveryReading.discoveryTemplateHome`).

Done in this branch:
- zh nav title 城瘾玩法 (en "Play guide" unchanged; existing UI tests key off it).
- Hero "三种玩法，即开即玩" + subtitle; per-mode tag pill (组队 · 按顺序 / 随时 · 自己走 / 无终点 · 散步), source descriptions and the "去看看" button (same `social.guide.<mode>` identifiers).
- Docs section header 玩法文档 / 规则与玩法细节; empty state 暂无玩法说明 / 内容上线后会出现在这里.
- Detail: title 玩法详情, source `createTime` meta line shown verbatim (`SocialInformation.createTime`).

Gaps / decisions:
- Source shows unusable docs as disabled rows ("内容待完善，暂不可查看"); iOS `SocialAccountService` filters them out (existing tested behaviour, kept).
- Source opens a doc in a half sheet; iOS pushes the detail (existing reopen/back UI tests depend on push).
- "现成玩法" copy (已玩 N 次, 更多玩法, empty copy) differs; `SocialGuideTemplateLocalizations.fragment.json` is hash-pinned by existing tooling, left unchanged.
- Source error states render a blank `load-failure` placeholder; iOS keeps its visible error + retry (strictly more informative).
