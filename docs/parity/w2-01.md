# w2-01 · Entry and authentication parity

The mini-program is the product source of truth: `liboyang42-cpu/hengyin` `chengyinhub-xcx/`, read-only.

- Branch: `cloud/w2-01-auth-entry`. It builds on `cloud/align-B-20261019` (entry/login is section 7 of `docs/alignment/xcx-ios-B-20261019.md`).
- Plan item advanced: reform plan v9 U03.

**What shapes this work:**
- **The mini-program has no login screen.** `app.js` logs in silently with `wx.login`, then `POST /api/login/code` creates the account on first use. There is no phone-OTP login, no password login and no registration/onboarding page. Phone UI exists only for WeChat `getPhoneNumber` binding (profile page) and for the deregistration second factor.
- **A native app has no silent credential.** iOS keeps an explicit sign-in: 玩家注册 / 商家注册 / 先逛一逛, then phone OTP. It uses the backend's native endpoints `/api/login/phone`, `/api/login/apple` and `/api/login/wechat/app`, which return the same `{token, data:{id,userType,avatar,nickname,role}}` shape as `/api/login/code`. The role still comes from the server.

## Reform plan v9 U03

`Core/BeijingBusinessTime.swift` is the shared helper. Its rules:
- A bare server time is Beijing wall time; an explicit offset is kept.
- A date-only value stays a calendar day.
- Display uses the phone's time zone, adding the Beijing time when the offset differs.
- Deadline hints use a server-time anchor on the monotonic clock, so wall-clock changes cannot move them. A reboot makes them unverified, a reconnect replaces the anchor, and the deadline second counts as passed.

Tests cover cross-time-zone display, a DST crossing, a changed phone clock, the boundary second and reconnects. The first consumer is the deregistration `executeAfter` row. The many existing per-feature `Asia/Shanghai` parsers are not migrated here, because they belong to other owners.

## Gaps and decisions needed

1. **Possible WeChat App login backend bug** (found by reading the backend, not tested). `/api/login/wechat/app` signs in through an identity check that compares the mini-program `wxOpenId`/`unionId`. A new App-only account (with `appOpenId` set, no `wxOpenId`, possibly no unionid) would be rejected. This needs verifying before WeChat App login is approved.
2. **Deregistration by WeChat reconfirmation cannot work natively.** It needs a fresh mini-program `wx.login` code bound to the account's mini-program openid. App accounts without a phone number need a phone-binding path or a backend alternative.
3. **Allowlist review needed** for `/api/config/features` (read) and `/api/compliance/consents` (app_launch AGREE write) before the flags reader and consent recording can be mounted.
4. **Privacy guide text** (`privacy_policy`) still needs approved source text.
5. **WeChat phone binding** (`/api/getwxbindphone`) is WeChat-only. The native equivalent would be SMS binding, which needs an SMS/product decision.
