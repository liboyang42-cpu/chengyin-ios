# w2-04 orders & participation — mini-program ↔ iOS parity

Branch `cloud/w2-04-orders-participation`. It is built on `migration/native-ios` merged with `cloud/align-C-20261019` and `cloud/align-B-20261019`.

The mini-program `liboyang42-cpu/hengyin/chengyinhub-xcx/subpackageMember` is product truth.

Reform plan anchors:
- **C01**: each screen records its data source, actions, and loading/empty/error states.
- **C02**: reuse the existing routes and service contracts.
- **C03**: centralised zh/en keys.

Status values:
- **parity**: fields, states, copy and the read call match.
- **partial**: some gaps remain; they are listed.
- **blocked**: needs a decision or a backend that is not available.

Writes are not live. These actions stay review-only, fixture-only, or behind the existing per-market endpoint allowlist, which is empty:
- pay, cancel, refund
- complaint submit
- template market, library and delete
- verification

No Apple build or XCTest was run, because there is no Xcode on Linux. Evidence is limited to the Python contract checks, the scaffold/ledger checks and the tree-sitter syntax checks.

## signup 票夹

**Status: partial.**

- **Mini-program:** `signup/index.*`
- **iOS:**
  - `App/TicketWalletView.swift`, `App/TicketWalletModel.swift`, `App/TicketWalletDetailView.swift`, `App/TicketWalletTeamView.swift`
  - `Core/TicketWalletContracts.swift`, `Core/TicketWalletSourceCopy.swift`, `Core/TicketWalletService.swift`
- **Entry:** Account → 票夹 sheet.
- **Reads (unchanged):**
  - `POST /api/registration/list {owner_type:1}` and `{owner_type:2}`
  - `POST /api/team/my`

**Done**
- Copy now matches the mini:
  - loading: 正在加载我的票
  - failure: 票夹没能打开, followed by the reason
  - signed out: 登录后查看票夹 / 登录后可查看你报名的路线票和场次票
  - empty: 还没有票 / 去首页发现路线或报名场次，票会在这里出现。
- Three existing keys changed their zh value in place; their English is unchanged, so UI tests that match English labels are unaffected.
- Title fallback depends on the lane: 路线信息待同步 for the route list, 活动信息待同步 for the activity list. Both the row and the detail header use it.
- Paid, unverified tickets show the 进入游玩 hint.
- The read-only footer no longer says teams are unavailable.

**Gaps and deliberate deviations**
- **Tapping a ready ticket** still opens the detail page first. Going straight to play would skip the tested rule that a fresh detail read must come before Play.
- **去支付** is policy-blocked. Pending tickets keep the existing pending-order entry or the unavailable notice.
- **Unknown status** shows 状态待确认, where the mini shows 待支付. This keeps an unknown ticket from being presented as payable.
- **One lane failing** still shows a banner, while the mini stays silent. Existing tests depend on the banner.
- **No pageNum/pageSize** in the request. The strict route guard and its tests require a body of `owner_type` only, and the mini only ever fetches page 1.
- **P2 items not done:**
  - per-ticket 我的队伍 row with member counts (the team entry is on the detail page)
  - swiper cards and background image
  - `focusId` deep-link focus
- **Toast-only cases** (票已取消, 票已过期, 场次信息待同步) stay as the existing inline notices.

**Tests**
- `Tests/CoreTests/TicketWalletSourceCopyTests.swift`
- `Tests/AppUITests/TicketWalletSourceCopyFlowTests.swift`, which runs against offline fixtures
- `Tests/ContractChecks/test_w2_04_ticket_wallet.py`
