# w2-04 orders & participation — mini-program ↔ iOS parity

Branch `cloud/w2-04-orders-participation`. It is built on `migration/native-ios` merged with `cloud/align-C-20261019` and `cloud/align-B-20261019`.

The mini-program `liboyang42-cpu/hengyin/chengyinhub-xcx/subpackageMember` is product truth.

Reform plan anchors:
- **C01**: each screen records its data source, actions, and loading/empty/error states.
- **C02**: reuse the existing routes and service contracts.
- **C03**: centralised zh/en keys.

Status values:
- **parity**: fields, states, copy and the read call match.
- **partial**: some gaps remain; they are listed.
- **blocked**: needs a decision or a backend that is not available.

Writes are not live. These actions stay review-only, fixture-only, or behind the existing per-market endpoint allowlist, which is empty:
- pay, cancel, refund
- complaint submit
- template market, library and delete
- verification

No Apple build or XCTest was run, because there is no Xcode on Linux. Evidence is limited to the Python contract checks, the scaffold/ledger checks and the tree-sitter syntax checks.

## mycanyu 我的参与

**Status: mostly at parity.**

- **Mini-program:** `subpackageMember/mycanyu/mycanyu.{js,wxml}`
- **iOS:**
  - `App/PlayerJourneyViews.swift` (`ParticipationHistoryView`, `ParticipationRow`)
  - `App/ParticipationParityViews.swift`
  - `Core/ParticipationParity.swift`
  - `Core/PlayerJourneyContracts.swift`
- **Entry:** Account → 我的旅程 → 我的参与.
- **Read call:** `POST /api/registration/my-joined`, no body. Unchanged.

**Done**
- Fill-style tabs 全部/未开始/进行中/已完成 as a segmented control. The list is read once and filtered on the client.
- Status follows the mini rules, in a participation-only projection; the shared `OrderLifecycleDetail.summary` is unchanged:
  - activity `cancelTime` → 活动已取消
  - paid + first scan → 已完成
  - free orders never show 不可退款
- Separate empty copy for the 全部 tab and for filtered tabs.
- Error title 参与记录没能打开, with the server message or the mini fallbacks.
- While refreshing, the list shows 正在更新参与记录…. If a refresh fails, the existing rows stay without a banner. A 401 still clears the rows.
- The status badge has a colour variant.

**Gaps**
- No cover image on rows (P2).
- No auto-back on error (P2).
