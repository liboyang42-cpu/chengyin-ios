## Reform plan v9 §16 / W10 (client side)

`Core/SecondRegistrationMetrics.swift` and `App/SecondRegistrationStatsView.swift` cover the client side of the second-registration metric:

- **Report display:** the mature 7/28/56-day N/D windows, free/paid transitions, exclusions, refund sensitivity, the supply-gap count, `as_of` and `metric_version`.
  - D=0 shows "无成熟样本"; immature cohorts show only the observed cumulative count.
  - Invalid cells show "未提供" and are never turned into a rate.
- **Client events:** an envelope for `offer_viewed` and `second_content_exposed`, carrying event_id, idempotency_key, occurred_at, schemaVersion, source, is_test, client_version and trace.
  - The envelope stays in a bounded, deduplicated local log with no transport, because capture is still a local proposal.
- **Not done:** no report endpoint or ingestion endpoint exists yet, so the screen is reachable only through `--second-registration-fixture` (DEBUG).
- **Server-side definitions, not built here:** valid registration, t0, maturity and exclusions.
