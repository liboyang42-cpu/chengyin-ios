# Merchant project recent activity

P064 goProjectMessages → P066 project-scoped recent activity. Normal entry: My account → Merchant → Projects → selected project summary → Recent project activity → loading / retry / empty or ordered activity rows → system Back → original summary. No unread badge, read receipt, or full-history claim. Read-only navigation requires no artificial mutation confirmation.

Existing project browser handles filtering/card/workspace navigation; the sealed event-ledger package maps events to finance. Neither provides this project activity destination. New functionality uses the existing access/me, project/my and merchant/events readers; services, routes, request bodies and permission definitions remain unchanged. The existing events service is owner-only, so this entry is owner-only as well; Mini visibility does not expand native grants.

Project keys derive only from known project/my bizType: topic → 1 and activity → 2, plus projectID. MerchantProject.ownerType describes ownership role and is never used as the numeric activity key. Unknown kinds and IDs outside Mini’s safe integer range fail closed. Event optional metadata accepts strings or integers, preserves string bytes, filters both keys and retains response order and duplicates. Existing content/time decoding and initializer behavior remain available. Missing or unsupported metadata means the row cannot be attributed, not a whole-store fallback.

Every load starts fresh access, checks selected merchant and existing projects grant, re-reads project/my to confirm the exact selected project, then reads events. Source snapshot/context, authentication, reader revision, cancellation and per-load generation are checked after each await. Refresh clears old rows; background/close retires the model; new loads suppress prior completions. Existing summary selection lifecycle is reused. The source returns only a recent store-wide window (Mini documents at most ten); do not paginate, fabricate counts or interpret empty as no historical activity.

Native UI adaptation places the Mini card bell in the existing native project summary; only projects already represented by that normal native browser are eligible. The existing parent store/merchant identity is not replaced with a guessed ID. Read failure is recoverable with explicit retry; leaving returns via the existing navigation stack. No backend modifications, writes, new grants or notification permission prompts. Canceled marketing direct activity creation remains untouched.
