## What changed (iOS)

| File | Change |
|---|---|
| `Core/SquareWorkspacePrivacy.swift` (new) | `SquareWorkspaceMediaEviction` + `SquareWorkspaceURLCacheEviction` (exact `URLCache.removeCachedResponse` per URL). `SquareWorkspaceFailure.isRevocation` matches business 404 only. `SquareWorkspacePost.isDeletedProjection`, plus `cachedMediaURLs` (absolute http(s) only). |
| `Core/SquareWorkspaceCoordinator.swift` | Every owner detail read now goes through `freshDetail`. A business 404, or a stale `lifecycle == DELETED` projection (handled as the same 404), calls `revoke(postID:)`. `revoke` drops the displayed `lastPost`, the history, the draft-list row, and unsent local edit hydrations for that post, then evicts their cached media. It keeps pending or receipted write-recovery entries, new-post drafts, and media still rendered by another visible row. `revalidate(postID:)` is the host hook to call after leaving a community, revoking a share or editing elsewhere: it drops the displayed copy first, then shows only a fresh authorized read. Edit readbacks (`adopt`) evict media the new version dropped. The drafts listing never shows DELETED rows. Optional `mediaEviction:` init parameter, defaulting to `URLCache.shared`. |
| `Core/TopicLikeDirection.swift` (new) | `TopicLikeOperationFactory` always sends `POST api/topic/like` with explicit `type=1`/`type=0`. `TopicLikeWriteOutcome` decodes the msg-only `AjaxResult`; the acknowledgement is not treated as like state. `TopicLikeLedger` keys state by account and epoch. It coalesces duplicate taps, and only the newest intent can settle. A readback confirms only if it started after every write finished. If the readback disagrees, it is shown as a mismatch, and server truth wins. An unknown outcome blocks any resend until a readback. An account or epoch switch or a 401 drops everything. |
| `Questify.xcodeproj/project.pbxproj`, `tools/current_ci_manifest.json` | Regenerated with `tools/generate_project.py` / `tools/current_ci.py refresh --base <integration SHA>`. |

Not changed: auth, RBAC, DTOs, endpoints, requestIds, UI pages, approvals, entitlements, deployment target. The workspace in `AppSession` still has `service: nil` with all grants off. The like factory and ledger have no transport or UI entry, so they stay OFF until an approved caller wires them in.

## Tests added (QuestifyCore XCTest)

- `Tests/CoreTests/SquareWorkspaceRevocationTests.swift`: these tests use the B05 fixture values and cover:
  - the author's old link after deletion returns 404, and media is evicted
  - a stale DELETED projection returns 404, and history is not fetched
  - another viewer's legal public media is never evicted
  - a timeout clears the display only, with no eviction or discard
  - an unsent edit hydration is dropped while recovery entries and new drafts are kept
  - an edit evicts only the removed media
  - shared media stays cached
  - DELETED draft rows are hidden
  - `URLCache` eviction is exact
- `Tests/CoreTests/TopicLikeDirectionTests.swift` covers:
  - explicit `type` for both directions, never omitted
  - outcome decoding
  - like → unlike → like settled by readback
  - duplicate coalescing
  - out-of-order responses
  - a stale read before a newer write
  - unknown and rejected outcomes
  - account and epoch switch
  - sign-out and 401

Existing `SquareWorkspacePrivacyReadbackTests` should keep passing unchanged. `revoke` keeps an in-flight history read's generation, so it still reports `.rejected(404)`.
