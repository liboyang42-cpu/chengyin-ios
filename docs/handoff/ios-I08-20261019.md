## What changed

| Area | Change |
|---|---|
| NPC log deletion (BK-EXISTING) | New `Core/NPCChatLogDeletion.swift` wraps the existing POST `api/ai/npc/chat/data/delete` (login identity only, empty `{}` body like the mini program) and decodes `{deleted:n}`. **Default OFF.** It needs its own exact `OperationEndpointApproval`. The export read approval, chat/model grants and generic compliance writes do not authorize it. `AccountComplianceCoordinator.npcChatLogDeletion` is a dormant hook that defaults to nil, and no host injects it. |
| Outcome semantics | A confirmed `{deleted:n}` (0 included) is the only success. If the request was sent but the response was lost, came back non-2xx (not 401) or had no readable count, the result is `unknown`. It is never resent or guessed as 0. A 401 or a business `code != 200` is a definite "not confirmed". An account, epoch or token change after sending discards the result. |
| Coordinator | `NPCChatDataCoordinator` offers deletion only over records already read for the same session. Deletion needs an explicit confirmation and sends once per confirmation. Close, background, account change or a reload retires the confirmation or the in-flight request, and a late response is ignored. After any outcome the shown text is cleared and the export is read back once, so logs written later by a late reply stay visible. Read and reload are blocked while the delete is in flight. |
| View | `NPCChatDataView` shows a destructive button and a confirmation dialog (strings in the new table `Resources/NPCChatLogDeletion.xcstrings`, en and zh-Hans). The copy says **log deletion only**: request receipts and audit records are not covered, and a reply in flight may write a new log. Unknown and failed states are kept separate from the confirmed count. The dialog binding cannot cancel an intent that was already confirmed. |
| BK-AI unknown receipt | Added a regression for the frozen A02 fixture (`PROCESSING/UNKNOWN/REQUEST_OUTCOME_UNKNOWN/retryable=false`, with safeText present). It never becomes a history turn, keeps the original requestId, offers no send or retry, and sends no second request. Existing merchant and shop NPC source already handled this. No source change was needed. |
| Usage (tokenIn/tokenOut/tokenEst) | Verified that no iOS source decodes or displays these fields, so the app cannot render an unknown cost as 0. No DTO fields were added. The admin Vue `tokenEst \|\| 0` display belongs to Claude/admin (AI-VOICE note) and is not iOS work. |
| AI unavailable | Verified that the existing iOS AI surfaces (template assist, ShopNPC, merchant NPC) never show sample text on failure. ShopNPC decode has no legacy `data.text` fallback. No new paid, memory or voice scenario was enabled. |
