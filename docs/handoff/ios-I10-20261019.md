## What changed

| Area | File | Change |
|---|---|---|
| Signposts (new) | `Core/NativePerformanceSignposts.swift` | Static catalog of six Points of Interest (subsystem `Questify.Performance`, category `.pointsOfInterest`). Names are `StaticString`s. No account, route, coordinate, URL or content value is ever attached. Intervals end idempotently. |
| Map hot path | `App/WalkingNavigationView.swift` | `walking.refreshTick` wraps each synchronize/update tick. `walking.cameraFit` wraps the explicit camera buttons. Route coordinates are now converted once per render instead of twice (casing and route share the geometry). |
| Map / long list | `App/PlayRouteMapView.swift` | Each annotation used to rebuild a `PlayRouteMapCamera.Read`, and each Read re-projected every stop. That made the work grow with the square of the stop count, and also applied when a preview was active. Now one Read and one preview resolution are built per render (`playRoute.mapProjection`) and shared by all pins. `playRoute.cameraFocus` wraps focus. |
| Image hot path | `App/QuestifyProgressiveBlurArtwork.swift` | `image.artworkLoad` covers fetch, decode and render per load. It closes on cancel, retire and every early return. |
| Audio hot path | `App/NativePlatformAdapters.swift` | `audio.startToPlaying` runs from `start()` until `.playing`. It also ends in `stop()`, so failure, interruption, retry and teardown never leak an open interval. Observers are unchanged. |
| VoiceOver | `App/PlayRouteMapView.swift` | The "Current stop" label is now a header. Actionable pins get a hint (`playRouteCamera.notice`, an existing key) saying that preview only moves the map. The existing `.isSelected` trait is kept. |
| VoiceOver | `App/WalkingNavigationView.swift` | The step row that shows the "Next step" cue also has the `.isSelected` trait, so the meaning is not visual only. |
| Reduce Motion | `App/WalkingNavigationView.swift` | The map transaction now drops animation under Reduce Motion (system, in-app preference or UI-test flag), as it already did under Low Power Mode. |
| Measurement | `tools/signpost_measure.py` | Has four commands: `record`, `export`, `summarize` and `compare`. Names are read from the Swift catalog so they cannot drift. `record` and `export` refuse to run outside macOS. |

No new localization keys. No new capability, background mode, entitlement, signing or deployment-target change. No SwiftUI rewrite to mimic mini-program components.

## Device measurement checklist (real iPhone)

Use the same iPhone, iOS version, build configuration and Low Power Mode state for both runs. Record the model, iOS version and commit SHA. Capture the **before** run on `integration/wave2-20261019` *plus only* `Core/NativePerformanceSignposts.swift` and its hooks, or capture an Instruments Time Profiler pass on the base. Capture **after** on this branch.

1. Build and run on the device: Release-like, Debug off where possible, unsigned per repo rules (sign locally only for your own device; do not commit signing).
2. `python3 tools/signpost_measure.py record --device <UDID> --output before.trace --time-limit 120s` (template `Logging`; pass `--template` if your Xcode names it differently).
3. Run the same scripted scenario for each hot path. Repeat each 5 times:
   - **Map (walking):** open a walking destination, start, let it run for 60 s in the foreground, then tap "Show route" and "Show destination". Points: `walking.refreshTick`, `walking.cameraFit`.
   - **Map / long list (route map):** open the orientation route map with the largest real route available. Show the map, then preview 5 stops through the menu and 5 by pins. Scroll the stop list top to bottom. Points: `playRoute.mapProjection`, `playRoute.cameraFocus`.
   - **Image:** scroll the home feed or object cards over 30 cards that use progressive artwork. Point: `image.artworkLoad`.
   - **Audio:** start, pause, resume, and stop and restart a narration/voice clip 5 times. Unplug headphones once. Point: `audio.startToPlaying`.
4. `python3 tools/signpost_measure.py export --input before.trace --output before.xml`, then `summarize before.xml --label before > before.json`. Repeat for after, then run `compare before.json after.json`.
5. Also note, from the Instruments Allocations, Leaks and Hitches tracks: peak memory on the map screens, whether memory returns after popping each screen (leak check), hitches during list scroll, and battery state.
6. Accessibility pass on device: VoiceOver on, Dynamic Type at AX5, Reduce Motion on, then repeat the route map and walking steps. Check that pins read "name, state" plus the hint, the current step announces "selected", and nothing animates the camera.
7. Keep traces and summaries local. Do not commit them, and do not mix them with synthetic UI-test screenshots. Do not rank devices by AR/3D source counts. Rank only measured intervals and hitches from the same scenario.

## Decisions

- **The route-map refresh Task is not cancelled on disappear.** `PlayExperienceCoordinator.load()` belongs to the parent journey screen. Cancelling it when the map is popped would move the shared coordinator to `.failed` for the parent. The coordinator already uses `generation` and session checks to retire late responses.
- **Walking keeps one structured `.task(id: scenePhase)` loop.** It is cancelled on disappear, and the model is paused in `onDisappear` (existing behavior).
- **Walking step rows keep `id: \.offset`.** Provider steps have no business ID. The row index is the step's identity within one immutable route, and a new route replaces the whole list.
- **No sheet draft is lost.** The steps sheet holds no input. Route-map navigation leaves `selected` only through the existing retirement rules.
- **`PlayExperienceView.swift` is untouched** to avoid conflicting with #30 (w2-11). Its own `Task { await model.load() }` refresh has the same shared-coordinator semantics as above.
