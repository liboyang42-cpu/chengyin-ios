## Change

- `Core/PlayGameCommandJournal.swift` (new): `PlayPendingGameCommand` stores the exact envelope (payload as
  sorted-key JSON), the owner (`PlayRecoveryOwner`), the origin epoch and the projection sessionId.
  `PlayGameCommandJournal` (read / record-if-empty / clear-by-generation) and a synthetic memory adapter.
- `Core/PlayDurableRecovery.swift`: a third encrypted slot (`<key>:game`) conforms to the journal. It is bound to
  the same owner/realm key as the completion slot, never shares or blocks it, and rejects foreign owners.
- `Core/PlayGameSessionRuntime.swift`: `PlayPlayerGameCoordinator(..., journal:)` defaults to `nil` (existing
  behavior). With a journal:
  - The lock is recorded **before** the first byte is sent. If the write fails, nothing is sent and the
    journal is re-read on the next load.
  - `load()` adopts an existing lock for this owner/activity. An unreadable, foreign or tampered lock fails
    closed (`persistenceUnavailable`) and blocks new commands.
  - The lock is released only after an APPLIED receipt *and* a matching projection readback (same sessionId,
    revision ≥ receipt), or after a FAILED receipt. A failed release keeps the command pending, and
    `retryExact` then only repeats the readback/release without a POST.
  - It is never released on PENDING, a missing receipt, a read error, cancellation, account/realm switch or
    page exit.

## Tests

`Tests/CoreTests/PlayGameCommandJournalTests.swift` (12 methods, QuestifyCore XCTest) uses the sanitized A01
values (requestId `a01-ready-71`, expectedRevision 4 → APPLIED revision 5, receiptId 501). It covers:

- lock persisted before dispatch
- restart reads back by the original key without posting
- restarted `retryExact` sends an identical envelope with the refreshed token, and readback releases the lock
- FAILED releases the lock
- missing/PENDING/AjaxResult/network replies plus page exit keep the lock
- APPLIED with a failed or other-session view keeps the lock
- unwritable journal never dispatches
- unreadable journal blocks new commands
- failed release retried without posting
- other account/realm gets its own slot, and the same account with another role fails closed
- a late reply after an account switch leaves the original lock
- second device refreshes the view
- tampered/foreign-activity record fails closed
- plist round-trip of submit/hint/choice payloads
