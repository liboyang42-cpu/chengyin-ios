## CY-HANDOFF: IOS

- iOS branch/SHA: `cloud/w3-I04-quote-asset` (see PR head); card I04; BK-ASSET.
- **H1 cart redemption has no ledger row.** `UmsMemberCartServiceImpl.settleCart` deducts points via
  `deductPoints` without inserting `ums_member_points_detail`. Repro (source read): settle any cart with
  a positive points cost → member point decreases, `api/points/list` shows no row. Expected: an
  independent ledger fact for the deduction (BK-ASSET "independent readback"). Actual: only the
  `oms_order` exists. Proposed contract: none from iOS — owner decides whether the existing
  points-detail writer covers it with the order id as eventId. Blocker for iOS: mall redemption
  readback cannot use `readBackPoints`; iOS keeps the redemption lock as is.
- **H2 points returns have no ledger row.** `returnPointsToUser` / cancel-unpaid `addPoints` paths
  increase points without a points-detail row, so a refund's points return is visible only through
  `pointsReturned` on the cancellation feedback, not through the ledger. Same proposal: owner decision; no iOS field requested.
- **H3 checkout preview has no `pointBalance`.** `previewSettlement` never sets `MemberCartVO.pointBalance`,
  so the dormant iOS redemption review always refuses with `changedPreview`. iOS keeps that (no
  coalescing to 0, cart stays at its current admission). No new field requested.
