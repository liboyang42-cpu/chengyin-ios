## Change: received-stamp read (I11)

`Core/RoamReceivedStampRead.swift`:

- `RoamReceivedStampReadRoute`: exact received path, then delegates to the existing album canonical-pagination validator (POST multipart, exactly `pageNum`/`pageSize`, size 1–50, no query, fragment or extra fields) and the response validator (page echo, unique positive ids, `list.count ≤ pageSize`).
- `RoamReceivedStampReadAccess`: a grant whose paths must equal exactly `[api/roam/stamp/received]`. It cannot be satisfied by the album grant, the exchange route or a combined set, and binds market CN, server role, account, namespace and endpoint.
- `RoamReceivedStampService`: an HTTP 401 / business 401 response is unauthorized; other business codes, HTTP errors, a null `data`, a wrong page echo or duplicate ids are errors, never an empty page.
- `RoamReceivedStampReader: RoamExperienceReading`: only `album(page:pageSize:)` is served, so the existing `RoamAlbumPager` (dedupe, `isVisible` moderation filter, generation fence) pages received stamps. Account, epoch, viewer or grant changes retire in-flight replies with `CancellationError`. Unauthorized replies notify only the captured context. Every other roam read throws `notConfigured`.

Nothing constructs this grant in `AppSession` or a view, so the read is **OFF** in every build. `Core/RoamExperienceService.swift` and its exact-route contract check are untouched. Mounting a "received" tab in the album view (`App/RoamExperienceHubView.swift`, which open PRs #10/#25/#26/#30 edit) and a reviewed grant are left as follow-ups.

## Open CY-HANDOFF items

**IOS-I00-1: `/api/userInfo` carries no server role**

- iOS: `cloud/w3-I00-I11-baseline-entries`, card I00. BK: none fits exactly (closest is BK-SESSION/A01 session contract; OPT-001/003 C00 baseline).
- Repro (sanitized): POST `api/userInfo` with a valid session token. Master `ApiLoginController.userInfoView` returns `{"appUser":{"userId":17,"nickName":"…","userType":1,…}}` with no `role`.
- Expected by the native session contract (`docs/cn-native-session-contract.md`): `appUser.role ∈ {player, club, merchant}` from the server. Actual: key absent, so native login readback and cold restore always fail closed (pinned by `I00SessionAdmissionBaselineTests`).
- Proposed contract (for C00 to decide; not implemented here): either (a) add `role` to the `userInfoView` whitelist with the same value as `/api/role/info` `data.role` (`roleService.resolveRole`), or (b) C00 freezes `/api/role/info` as the native role readback and iOS adapts in a separate card. No native fields are invented and no fallback is added meanwhile.
- Blocker: CN native activation also still needs a reviewed endpoint/realm, SMS provider, legal content and an authorized test identity. Everything stays OFF.

**IOS-I11-1: team report write has no replay contract** (informational; no native wiring requested). POST `/api/team/report` returns `taskId` but takes no requestId, so a lost response cannot be distinguished from a non-submission. If native ever adopts it, a frozen contract with a stable request identity, or a readback, is needed first.
