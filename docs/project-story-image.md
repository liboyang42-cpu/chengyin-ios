# Story image selection and local application

The ordinary professional chapter editor now opens an image review instead of appending an empty image block. The same bounded flow replaces an existing image. The selected-only native picker, metadata-clearing renderer and source-aspect crop run locally. A separate explicit action uploads the reviewed JPEG with the existing `/api/common/uploadOSS` multipart `file` and `bizType=image_free` contract. Applying its exact returned URL saves the captured local draft through the existing editor storage path.

This path is default-off: production composition supplies no upload approval, no approved returned origins and no picker approval by default. Configuration changes must go through the existing synchronous project configuration boundary. Both original factories and transport clones reject stale viewer/configuration generations, including revoke-and-restore. Merchant drafts and staged chapter overrides are outside this first image slice and display unavailable.

The target captures the owner, persistent draft bucket, editor visit, full draft bytes, chapter and original image block. Existing content stays unchanged before explicit application. Story reordering, deletion, restore, discard, account or configuration changes retire stale actions. A replacement updates only its captured image URL. The existing 500 UTF-16-unit story URL limit remains; oversized returned URLs retain their receipt but cannot be applied. Prepared review shows references only from its captured payload, in serialized block order, without fetching arbitrary image URLs.

The local journal saves an intent before an upload task is scheduled. It stores the exact returned reference before application. A received-but-unstored receipt is kept separately from display state and can recover locally after closing and reopening within the same app session. This memory cache does not survive process termination. Uploads with no saved response remain unknown; the legacy producer has no status/idempotency API, so no retry is automatic. A separately chosen and explicitly uploaded image creates a new attempt. The journal is bounded to 256 records and 4 MiB; it fails closed at capacity, without deleting prior history.

Draft saving and upload-receipt saving are separate existing storage operations. A partial draft-envelope/active-pointer failure is reported and does not replace the visible draft. The retained exact receipt can retry only the local save, and a deterministic block identity prevents duplicate insertion when an application-marker write failed after the draft was saved.

The upload response is a legacy URL reference, not the owned-topic-cover asset contract or rights/immutable-content evidence. The W02 text-only release compiler remains unchanged and refuses unsupported media dependencies. The local preview displays only sanitized selected bytes; no claim is made that it re-read the server body. Audio upload is the next separate source-backed slice. No microphone or audio playback is introduced here.
