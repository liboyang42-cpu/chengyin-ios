# Owned template shelf pagination

Source: private mini/backend at 11be8cb2f09073496f3a7d5130d558da60cf5439. All five prior capture blobs were reverified against Git blob hashes after the documented one capture-added terminal newline normalization. No private source bytes are included here.

The actual mini mytemplate page posts to existing `/api/template/my-list` with pageNum, pageSize 10, keyword, empty is_quote and category_id. It consumes `data.rows` and optional total. Although mini has a category selection handler, the current request always sends empty category_id; this implementation does not invent a working category filter. Backend authenticates membership and resolves owner scope before PageHelper pagination. No merchant scope, entitlement, paid license or public fallback is introduced.

A separate presentation-only reader handles explicit continuation/retry, keyword refresh, generation/session/epoch/authorization revision cancellation, positive typed member identities, duplicate refusal, known total and unknown-total full-page continuation. Empty pages stop continuation even when total is stale. An explicit local 100-page/1,000-row guard stops unbounded reads and explains the limit. A failed continuation retains prior rows and retries the same page. Refresh clears earlier results. Overlapping pages are refused rather than silently merging a shifted offset snapshot; refresh is offered. The endpoint does not provide snapshot consistency or per-row ownership evidence, so this is no claim that pagination establishes either.

The production adapter remains dormant. The existing adapter's canSubmit authorization gate is unchanged; no transport is mounted and no grant enabled. The dormant wire builder only additionally accepts exact bounded read-only page10 descriptors. Default read attempts still fail unavailable.

Owner-write state is deliberately separate. Existing listMine first100, fresh exact-row preflight, durable pending locks, library/delete payloads and acknowledged absence reconciliation remain unchanged. UI write controls require the complete displayed row to match the existing owner's first100 snapshot. Browsing later pages grants no write authority; later-page writes outside that snapshot remain unavailable. No new endpoint, owner inference, authorization, publishing, production request or paid-license behavior is added.
