# W17 App reward experience — local prototype

This source slice extends the existing normal account collection navigation and Questify card/list styling. My Rewards is separate from the deployed owned-coupon/code flow. The initial prototype had no network reader. The separately reviewed reader unit adds source-backed list/detail transport and session fences, while AppSession keeps its service nil. There is still no issuance, credential factory, stock write, payment, random selection or local redemption operation. Normal builds show a truthful unavailable state. Existing coupon navigation is retained.

The domain projection is deliberately not Codable; a separate validated wire adapter now handles the read contract: PHYSICAL only, THEME/MAP context, award/context/release/instance/rules/merchant/store references, title, quantity, frozen validity and redemption conditions, AWARDED/REDEEMED/EXPIRED/REVERSED, awardedAt and asOf. The instance is the THEME run or MAP season; it is not inferred from enrollment. This is coordinated with the unpublished backend inventory and read API slices; it is not a deployed API claim. Reservations are not awards. A redeemed item cannot be reactivated by this model. Missing conditions, invalid quantity/window, terminal states and exact expiry fail presentation closed. Local date checks never authorize redemption or expire/recycle inventory.

DEBUG launch arguments `--uitesting-rewards-scenario content|empty|failure` expose synthetic examples through the same normal account destination. Dates are fixed explicit synthetic terms, not a 30-day policy. The presentation sheet intentionally has no QR code or valid credential; opening/closing it never consumes anything. Background, scope change, logout and navigation departure dismiss presentation. Conditions, account binding, single-use expectations and staff authority are explained in English and Simplified Chinese. No secret is copied, persisted or displayed.

## Verification boundary

Authored Core XCTest tests cover exact expiry, not-yet-valid, terminal states, malformed conditions/quantity/window and repeated presentation with immutable state. Authored UI tests traverse the normal synthetic integration root, sign in, account entry, detail, sheet close/reopen/back, terminal-state blocking, retry and disabled production default. Python source checks only verify boundaries and catalog presence. These do not establish compilation, runtime accessibility, UI correctness, clock behavior or security.

Swift/Xcode are unavailable here. Swift tests, iOS app/UI compilation, simulators/devices, VoiceOver/Dynamic Type, foreground/session interruption timing and bilingual rendered screens remain UNRUN. No remote CI or publication was started. Actual activation requires publication and approval of the source-backed owner-scoped reader, live verification, fresh server state, short-lived audience-bound presentation credentials, staff authorization, anti-replay and atomic one-use redemption, plus real service and runtime evidence. No UI-only check substitutes for any of those gates.
