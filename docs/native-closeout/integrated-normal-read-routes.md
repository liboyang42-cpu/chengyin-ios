# Integrated normal-App read routes

This is an additive offline integration of the independently reviewed signed-in Activity/Topic details, Play nodes/route-state reads, and explicit manual-area map reads. It does not enable a deployment, runtime grant, live network/provider, payment, registration, gameplay write, or public catalog/home grant.

The transport accepts query-bearing URLs only when the complete request matches either `ManualMapReadRoute` for the captured explicit area or `PlayReadRoute`. Each branch then independently requires its own root grant, complete signed-in identity and, for manual-map/Play, current runtime approval. Detail multipart routes retain their separate typed deployment grant. Public template/home-list and owner/private-home approvals remain separate.

`CompositionHTTPTransport.copy` is the single transport-clone seam. Both `scopedForManualMap` and `replacingUnderlying` preserve the complete deployment, area selection, owner/manual approval selectors and current identity source. Mutable `playReadConfiguration` is forwarded through the parent transport instead of snapshotted, so a clone created before AppSession finishes callback installation, or before later replacement/revocation, observes the current selector. AppSession's selector still weakly captures its session; clones do not retain the session. Temporary clone chains retain their parent transport for current selector resolution.

Play retains explicit stable caller-owned approval issuance, live path-set and viewer revision keys, current read-specific dependency factories, and a reads-only rich service. Manual-map retains explicit independent area selections, approval issuance/expiry and final decoded reader checks. Signed-in details retain actual owned-task cancellation and authoritative viewer fences. Transport checks identity/approval immediately before dispatch, after success and on error. These protections do not grant authority to an unrelated route or capability.

`IntegratedReadCompositionTests` adds ten App-hosted XCTest cases covering both clone orders, late mutable Play installation/revocation, all eight combinations of the three root grants, independent runtime approvals, cross-family query attacks, legacy-grant separation, guest/partial identities, area replacement, same-viewer approval reissue and all-family viewer/task cancellation. The existing independently reviewed Core/App/UI cases remain included. Python source assertions and Tree-sitter parsing are supplementary only: Swift typecheck, XCTest, Xcode builds and simulator/device acceptance must run on the exact final integrated bytes before any readiness claim.
