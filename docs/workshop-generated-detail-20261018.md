# Generated professional template detail handoff

Baseline: 13c5be211e7e03e2f447e2e061840917fab9846b.

## Scope
Complete the historical creation receipt → view → independently authorized current owner detail → retry/close/return subflow. This is not completion of the whole workshop requirement. No creation, installation, purchase, publishing or permissions are added.

## Implementation
- Only a matching CREATED operation belonging to the current professional appearance exposes its positive template ID.
- A fresh detail selection freezes its UUID, operation, controller revision and existing independently approved owned-template reader at click time.
- The existing owner transport fetches api/template/myinfo and verifies both requested template ID and current member ID. History metadata and install/professional grants do not issue a shelf-read grant.
- Current detail uses the existing read-only display, failure and retry path. Close returns to the unchanged creation receipt.
- Close, dismissal, backgrounding and parent departure retire the selection. Any controller action synchronously changes the detail revision, including equal-receipt refreshes. A captured sheet binding ignores stale dismissals.
- The optional acceptsResult fence reaches the transport before dispatch, after response and before unauthorized handling. A closed visit's late 401 cannot expire the current account. Existing reader callers retain their default behavior.
- Existing registered Swift files only. No project file or localization hold was changed; existing member-template and close labels are reused.
