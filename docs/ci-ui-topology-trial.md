# Bounded ten-shard UI trial

The 402-method source inventory is partitioned into ten exhaustive class-level shards. This trial addresses the observed five-runner concurrency limit: six long UI jobs can leave a nearly full-length second wave. Required `native` aggregate naming, exact commit/toolchain binding, all build/AppUnit/security gates, 28-minute test-process deadline, 35-minute UI-job ceiling and one-day artifacts are unchanged. All ten unique successful completion outputs must match the same build fingerprint. Missing, stale, skipped or failed output remains failure.

The timing profile separates successful `method_seconds` observations from 23 declared `estimated_method_seconds`. Successful observations always take precedence. The unobserved baseline is 60 seconds; known pending locale/scenario loops use 60 seconds per launch (360/240/120 seconds), with 60 seconds for the expiry case and each new walking case. These are conservative grouping assumptions, not measured healthy runtime or guaranteed upper bounds. No failed or interrupted case duration is treated as a successful measurement. New source remains the inventory; no profile entry can remove a test.

[Run63](https://github.com/liboyang42-cpu/chengyin-ios/actions/runs/37032216443) measured five occupied macOS slots and a 28-minute queue before its last UI shard. [Run66](https://github.com/liboyang42-cpu/chengyin-ios/actions/runs/37043805752) supplies newer builder/device/US/AppUnit costs and separate assertion/deadline evidence. Models include setup, body, finalization and auxiliary-job contention, not body sums alone. With the conservative pending inventory, eight shards leave about 9 seconds under the process limit in the observed-body-slowdown stress; ten leave about 4 minutes 49 seconds.

Ten projects approximately 65–71 minutes total under the two observed start orders, but a tested adverse order reaches 78.2 minutes. Ten uses approximately 12 more macOS runner-minutes than eight. These are projections, not achieved savings or scheduling guarantees; new compile/runtime cost remains unmeasured. This bounded trial must be evaluated using the actual complete same-commit run. It does not enable paid runners, new permissions, skipped tests or automatic timeout increases.
