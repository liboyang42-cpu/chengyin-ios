## Verified defect and repair

`AccessibilityFixtureOptions` recognizes `--uitesting-dark`, but the Chinese
large-text Social draft, Square report and Settings copy-failure tests passed
`--uitesting-dark-mode`. That spelling did nothing. All three roots route through
`ModuleFixtureRootView`, whose shared modifier was already correctly attached.
The Social screenshot `4FD1604B-C029-47D5-9057-AE976A651C46.png` from the earlier
published run was reported as light; its name was not evidence of dark mode.

The three callers now use `--uitesting-dark`. Each affected scenario explicitly
asserts actual dark + accessibility3 after launching, independently of what its
launch-argument array contains. The Chinese text, controls, draft retention,
keyboard dismissal and nested-sheet assertions are preserved.

The existing DEBUG-only `module.fixture.notice` receives an accessibility value
from a separate descendant modifier reading SwiftUI's `colorScheme` and
`dynamicTypeSize`. It does not read process arguments or set either environment
value. The value has the form:

`colorScheme=dark;dynamicTypeSize=accessibility3`

The XCTest helper waits for the expected value before continuing. This catches an
ignored flag or a detached root modifier on Apple execution; merely checking the
launch arguments cannot establish that. All existing custom-display-flag callers
through the module root now have a corresponding environment assertion. A new
synthetic case checks that max text takes precedence when both size flags exist.
No additional visible overlay or production diagnostic was added.

## OS-level Dynamic Type conventions

Before this repair, SettingsNative and NativeSettingsReuse used
`-UIPreferredContentSizeCategoryName UICTContentSizeCategoryAccessibilityXXXL`.
Those module cases now use the recognized `--uitesting-max-text` and assert actual
accessibility5. Their English/Chinese and navigation assertions remain intact.

TemplateAuthoring and TemplateOwnShelf still use the OS-level preferred-content-
size launch convention. Their direct fixture host does not use the shared
accessibility modifier. Only harness buttons are clamped to `.large`; the authored
content inherits the OS size. Actual content size for these tests is unverified
here and is not covered by the new module notice.

## Coverage and verification boundaries

A module-root environment observation is not a per-page or presented-sheet
measurement. Sheets, popovers, UIKit bridges and deeper size overrides can have
their own environments. This packet does not add probes to production content or
claim that every screen, nested presentation or pixel is verified. Existing
screenshots named “light” without an explicit verified observation remain
inherited-appearance captures, not proof of forced light. Physical-device settings,
VoiceOver, full accessibility audits and all production/live acceptance remain
separate. Reduced-motion behavior is unchanged, not newly validated here.

- [preferredColorScheme(_:)](https://developer.apple.com/documentation/swiftui/view/preferredcolorscheme(_:))

Runtime acceptance of these authored assertions still requires the Apple jobs.
