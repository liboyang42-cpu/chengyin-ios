## Integrated behavior and boundaries

- Public club post/feed/comment/history views are reachable from normal Club home/detail, outside governance/management conditions. AppSession retains one coordinator and uses its actual ClubReadIdentity/account epoch. Fresh membership plus exact post/comment reads are required; rows absent from the first fresh page are conservatively rejected rather than guessed. Default transport cannot send HTTP, mutation grant remains disabled, images remain disabled, and unknown locks remain retained. Exact injected HTTP adapters remain executable independently of synthetic fixtures.
- Public merchant cards are linked from topic merchants using memberID as an owner ID. The existing typed inbound router now accepts canonical member and legacy row routes separately, still behind the empty HTTPS origin allowlist. Invalid/ambiguous IDs are rejected. Existing public-detail search/roam contracts and merchant invitations are untouched. Public review UI is wired through stable disabled readers; writes remain nil and image rendering remains nil. Returned profile IDs, eligibility and visibility remain authoritative. Public NPC destination remains nil: its future consumer must be MerchantNpcApi /api/ai/npc/merchant-chat using merchant-row ID, never play-node ShopNpc /shop-chat.
- Own-template shelf and authoring repair preserve exact multipart fields and template_id identity, separate from generic PublishModes id. The HTTP transport remains explicitly injected and disabled by default. Review, fresh exact-row checks, durable pending locks, acknowledged-only readback and unknown outcomes are preserved.
- GET /api/play/nodes chapter audioUrl is decoded into the same snapshot and joined by exact chapterID. Narration/guide share one player and require current-session, visible-node and server-unlocked authority. A separate questionAudio consumer is present only for that explicit field. Audio cannot emit gameplay evidence, completion or reward. All factories remain nil.
- Selected-destination Maps hosts are installed for topic nodes, free-explore PlayNode detail, roam POI detail, route preview and order detail. Order coordinates come only from omsTicket.gatherLat/gatherLng and meetingPoint, not the associated activity address. PlayNode coordinates are optional source latitude/longitude. Missing coordinates remain missing; no origin, player location or collectible ObjectCard is substituted. Copy fallback remains a separate explicit action.
- AppSession owns platform model lifetime and invalidates consumers synchronously before credential/account replacement; scope changes also reset host models. Each visible host gets a fresh model only when explicitly injected. Region configuration is immutable for the session lifetime. No audio/Maps native factory is supplied.
- Play normal/device/photo repair was applied as verified hunks, not a stale AppSession replacement. SessionPlayRuntimeView retains device/player/circle/stillness factories alongside new audio/maps parameters. Native camera/QR/location/motion implementations and photo upload/filter preview are present with empty device grants; upload review and completion review remain separate. No permission/plist grant was added.
- DEBUG-only club/public-merchant fixtures bypass AppSession construction; template own-shelf uses the existing fixture path. Catalog fragments are merged into Localizable because these views use the default table. The standalone original fragments remain documentation evidence, not duplicate runtime string tables.
