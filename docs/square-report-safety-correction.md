# Square generation safety correction

This follow-on patch addresses five review findings after the frozen Square report generation patch. Production report, mutation, media and legal grants remain disabled.

- Workspace detail decoding now follows the selected endpoint. Legacy `creativesquare/info` returns a flat `ViewCreativeSquare` containing `memberId`, `contents` and numeric `status`; it does not contain a community version or lifecycle. Legacy hydration keeps those values absent and records a digest of the authoritative source for subsequent stale-edit checks. Community decoding still requires a nonnegative version and nonempty lifecycle. Legacy objects cannot enter community publish or location-withdrawal commands.
- A report coordinator claims the shared target journal synchronously after all awaited policy and subject checks. Two coordinators waiting on preflight cannot dispatch different request IDs for the same target. The governance coordinator uses the same claim primitive.
- The report editor can reload the current qualified version of its exact original subject. A changed or expired snapshot clears the selected reason and review, retains the description, and displays the refreshed subject. Confirmation still strictly validates the reviewed version. Reloading performs reads only; a new review and confirmation are required before a mutation.
- Old saved edit drafts retain their existing envelope lane. Resume reads that exact endpoint and verifies ownership before supplying missing source metadata; it never probes another namespace. User text, media, references, workflow, receipt and pending state are preserved. A changed community version refuses automatic rebasing. Pending drafts cannot be rebound or unlocked.
- Old `delete:<id>` dispatch markers are retained and recognized only as legacy comment deletions. They do not lock or identify a community comment with the same integer ID. The generation-qualified legacy marker is added without removing the original.

New authored regression cases cover actual legacy response shapes, hydration/preflight/readback, unchanged community decoding requirements, old-envelope recovery, ownership and namespace rejection, pending-workflow preservation, a suspended two-coordinator preflight race, expired/changed report snapshots, and persisted old deletion markers across coordinator replacement and relogin. A synthetic UI case captures a refreshed report subject and requires a second review before simulated submission.

Local verification consists of source-contract checks, project/scaffold checks and a pinned supplementary Swift parser. Apple compilation, XCTest, XCUITest and screenshot execution require the separate Apple CI gate. No live API or report was sent. Legacy edit has no server version/CAS parameter: the source digest and fresh preflight detect observed changes but do not invent server-side atomic concurrency guarantees.
